## 1. 대원칙 7가지 (게시물 STEP 1~7)
1. **첫 3초(0초 첫 프레임)에 후킹 문장이 이미 화면에 있어야 한다.** 페이드인·빈 화면·로고부터 시작 금지.
2. **결과부터, 과정은 나중에.** "이렇게 입으면 이렇게 보인다"를 먼저 보여주고, 아이템 설명은 뒤에.
3. **"당연히 그런 줄 알았는데?" — 상식을 뒤집는다.** 단, 사실로 뒷받침되는 것만.
4. **손가락을 멈추게 한다.** 경고·실수·"이거 하지 마세요"는 스크롤을 멈추는 힘이 가장 세다.
5. **끝까지 궁금하게 만든다.** 결과를 첫 화면에 다 주지 말고 "몇 번째가 제일 쉬울까" 같은 여지를 남긴다.
6. **숫자로 증명한다.** 숫자는 시선을 잡는다 — 반드시 출처 있는 실제 수치만.
7. **타깃을 부른다.** "키 작은 남자라면", "출근룩 고민이라면"처럼 보는 사람이 '내 얘기'라고 느끼게.

## 3. 제작 규칙 (매 영상 필수)
- **후보 5개 → 1개 선택**: 영상마다 서로 다른 유형으로 후킹 후보 5개를 쓰고, 아래 체크리스트 점수가 가장 높은 것을 쓴다. 보고서에 고른 후킹 + 유형 번호를 적는다.
- **체크리스트**(각 1점): ① 0.5초 안에 읽히나(한 줄 16자 안팎, 최대 2줄) ② 결과·숫자·경고·타깃 중 하나가 있나 ③ 뒤가 궁금한가(답을 다 주지 않음) ④ 화면 속 옷과 바로 연결되나 ⑤ 사실인가(과장·허위 없음).
- **같은 유형 반복 금지**: history의 hook_type을 보고 최근 3일 안에 쓴 유형은 피한다. 하루 안의 영상끼리도 유형을 다르게.
- **캡션 첫 줄 = 화면 후킹과 이어지는 문장**(같은 말 반복 X, 한 단계 더 궁금하게).
- **허위 금지**: 숫자·통계·"~가 거짓" 주장은 반드시 출처 확인. 셀럽 이름으로 사실과 다른 이야기 만들지 않기. 나이·체형 비하 표현 금지("~면 안 돼요" 대신 "~면 이렇게").
- **기록**: history.json 각 게시물에 hook, hook_type(번호+이름) 저장 → 주간 성과 보고에서 유형별 3초 시청률·저장률 비교 → 잘 되는 유형을 늘린다.

## 4. 팀별 적용 위치
- **셀럽 스냅 해부 릴스(make_reel.py v4.3)**: look.json에 `hook`(후킹 문장, 줄바꿈은 \n) + `hook_cta`(커버 버튼 문구, 예: "바꿀 포인트 4개 →", "3번이 제일 쉬워요 →")를 넣는다. 0초부터 셀럽 이름 아래 어두운 판 위에 크게 표시되고 커버는 2.4초로 늘어남. 예: "흰 티에 이거 하나 걸쳤을 뿐인데" (21 작은 행동 큰 결과형).
- **Trend Daily(make_webtoon.py)**: 훅 장면(whook/pcompare)의 title 2줄이 후킹 문장. kicker는 타깃 호출(예: "키 작은 남자라면"), body는 궁금증 남기기(예: "3번이 제일 쉬워요 →").
  - ★ 2026-10-30 사장님 피드백: "하체가 신경 쓰인다면 이 글이 더 눈에 띄어야지, 그게 후킹인데" → 타깃 호출이 그 영상의 핵심 후킹이면(체형·고민·상황 타깃) 작은 kicker에 숨기지 말고 **큰 title 2줄**로 쓰고, 해결 문장은 body 한 줄로 내린다(예: title "하체가 신경\n쓰인다면" + body "타이츠 색부터 바꿔 보세요 →").
- **틱톡·유튜브 몰아보기**: 인트로 title 2줄도 후킹 유형 하나로(예: 15 흔한 실수형 "출근룩 실수 3가지, 몇 개 해당?"). 유튜브 영어 자막도 같은 후킹을 자연스러운 영어로.

## 5. ★ 유튜브·틱톡 몰아보기: 제목 = 첫 화면 = 썸네일 (2026-10-29 사장님 지시, 필수)
- 몰아보기 인트로 카드의 큰 제목(spec.title 2줄)이 곧 영상 제목이다. 유튜브 제목은 렌더할 때 나오는 `<출력>_title.txt` 를 **글자 하나 바꾸지 말고 그대로** 쓴다(한글 제목 + " | " + intro_en + " #shorts"). 제목을 따로 새로 짓지 말 것 — 바꾸고 싶으면 spec.title 을 고쳐 다시 렌더.
- 유튜브 설명 첫 줄, 틱톡 title·본문 첫 줄도 같은 한글 제목으로 시작(다른 후킹 문장으로 바꾸지 말 것).
- 썸네일 = 0초 첫 화면: 렌더 때 나오는 `<출력>_thumb.jpg`(인트로 카드 그대로)를 media_push 로 올려 Metricool `videoThumbnailUrl` 에 넣는다. VIDEO_THUMBNAIL_NOT_APPLICABLE 오류면 videoThumbnailUrl 을 빼고 `videoCoverMilliseconds: 0`, 그것도 거부되면 둘 다 빼고 예약(첫 화면이 이미 제목과 같으니 자동 썸네일도 최대한 맞게).
- 틱톡은 `videoCoverMilliseconds: 0`(인트로 카드). 검수자는 제목·첫 화면·썸네일 세 개의 한글 문구가 같은지 꼭 확인.
- 글씨 크기(10/29 사장님 지시 "글씨 잘 보이게, 후킹 꼭"): 몰아보기 인트로 제목은 **한 줄 6~7자, 2줄**로 짧게 — 그래야 썸네일에서 글씨가 150px 이상으로 커진다. "오늘의 몰아보기" 같은 밋밋한 제목 금지, 반드시 플레이북 26가지 유형 중 하나의 후킹 문장(유형 번호를 보고서에 기록). sub 한 줄은 20자 안팎(틸 띠 위 흰 글씨).
