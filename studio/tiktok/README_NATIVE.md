# ★ 틱톡·유튜브 = '네이티브 한 편' (2026-11-01 사장님 지시 — 이 문서가 README.md의 몰아보기 방식보다 우선)

> **11/2 추가 지시 (아래 내용보다 우선) — 목표·전체 규칙: studio/strategy/tiktok_10k_90d.md**
> 1) 틱톡은 **61초 이상**(32초짜리 영상은 사장님이 반려). 정지 화면 말고 아이템 클로즈업으로 늘리기.
> 2) **썸네일에 나온 코디가 영상 첫 장면**(썸네일은 빨강 코디인데 MA-1부터 나와서 반려됨).
> 3) **실사와 웹툰풍을 한 영상에 섞지 않기** — 같은 톤의 재료만 쓰기. A·B·C를 억지로 합치지 말고 가장 강한 주제 1개로 만들기.

사장님 피드백: "틱톡 영상이 짜집기한 티가 너무 난다. 재미도 없고 후킹도 없고 클릭률도 없다. 틱톡도 신경 써."
지난 7일 틱톡 실적(Metricool): 영상당 조회 64~136회, 좋아요 0~3.

## 짜집기 티가 난 이유 (다시 하면 안 되는 것)
1. 썸네일 격자 인트로("zzebi.st · 1분 몰아보기" + 작은 썸네일 3개) — 클릭할 이유가 없음
2. 검은 '01 / 03' 챕터 카드 — 흐름이 끊김
3. 영상마다 자기 훅·'저장 & 팔로우' 엔딩·'TREND DAILY' 번호가 그대로 나옴 = 이어 붙인 게 보임
4. 60초를 채우려고 정지 화면(투표 카드·틸 엔딩)을 늘림
5. 틱톡 제목이 캡션 요약("몰아보기 01… 02…")

## 새 규칙
- **길이는 억지로 60초 채우지 않는다.** 틱톡 크리에이터 수익 프로그램은 1분 이상 영상 + 팔로워 1만 명 이상이 조건이라, 지금은 조회수·팔로워가 우선. 목표 30~50초(트렌드는 내용이 충분하면 60초 넘어도 됨). 정지 화면으로 시간 채우기 금지.
- **0초 = 틱톡 전용 후킹 화면 = 썸네일 = 제목.** 그림을 화면 가득 + 아주 큰 후킹 글씨 2줄(한 줄 6~7자). 인스타 릴스 훅을 그대로 쓰지 말고 틱톡용으로 새로 쓴다(플레이북 26가지 중 하나, 그날 A·B·C 훅과 다른 유형). 예: "끝까지 보면 3번이 제일 쉬워요", "이 순서로 입으면 키 5cm" 처럼 끝까지 보게 만드는 문장.
- **한 흐름:** 영상별 훅·CTA·엔딩·챕터 카드 없음. 번호는 1/N 으로 하나만. CTA는 마지막에 2초 한 번.
- **틱톡 화면 가림:** 오른쪽 140px(버튼), 아래 25%(설명), 위 150px(탭)에 핵심 글자 금지.

## 도구
### Trend Daily → `make_tiktok_native.py`
오늘 A·B·C 대본 JSON과 그림을 그대로 다시 써서 make_webtoon.py 로 '한 편'을 새로 렌더(이어 붙이기 아님).
```
python3 studio/tiktok/make_tiktok_native.py native.json YYYYMMDD_tt_trend.mp4          # 틱톡
python3 studio/tiktok/make_tiktok_native.py native.json YYYYMMDD_yt_trend.mp4 --en     # 유튜브(영어 자막)
```
native.json 형식은 파일 맨 위 설명 참고. keep 으로 보드 장면을 4~6개 고르기(가장 볼거리 많은 순, 가장 쉬운/의외인 것은 끝에서 두 번째). hook.title 이 썸네일·제목. 렌더 약 4~5분.
### 셀럽 스냅 → `make_tiktok_comp.py` 의 `"native": true`
```
{"native": true, "kicker": "따라 입기 쉬운 순", "title": ["블랙 하나로", "분위기 3개"], "sub": "3번이 제일 쉬워요 ↓",
 "intro_img": "<첫 셀럽 원본 그림(글자 없는 것) 경로>", "intro_y": 0.3,
 "segments": [{"file": "...", "label": "...", "en": [[0, 2.4, "..."]]}], "seed": 7, "intro_en": "..."}
```
- 인트로 = 글자 없는 원본 그림 꽉 + 큰 후킹(영상 프레임을 쓰면 릴스 글자가 겹쳐 보이니 intro_img 필수).
- 각 릴스는 끝 3초 엔딩 화면을 잘라내고 바로 다음 릴스로. 챕터 카드·투표 카드·정지 화면 없음. 끝에 CTA 2.2초.

## 공통 결과물
`<출력>_thumb.jpg`(0초 화면 = 썸네일) · `<출력>_title.txt`(제목 그대로 사용) — 틱톡 title / 유튜브 title / 설명 첫 줄 모두 이 한글 제목으로 시작.
틱톡 예약: videoCoverMilliseconds 0, (가능하면) videoThumbnailUrl = thumb 공개 주소.
틱톡 본문: 첫 줄 = 제목(후킹) + 한 줄 궁금증 + 해시태그 4~6개(#패션 #코디 대신 구체적인 것: #키작남코디 #출근룩 등). "몰아보기 01 02 03" 목록 금지.

## 검수 체크 (독립 검수자 필수)
- 0초 프레임만 보고 '이걸 왜 끝까지 봐야 하는지' 알 수 있나 / 이어 붙인 티(다른 브랜드 표시·번호 리셋·엔딩 반복·검은 카드)가 없나 / 정지 화면 3초 이상 없나 / 틱톡 가림 영역에 글자 없나 / 제목=첫 화면=썸네일.

## ★ 틱톡 스토리 (2026-11-02 사장님 지시 "틱톡 올릴 때 틱톡 스토리도 같이, 인스타처럼")
Metricool은 틱톡 스토리 자동 게시를 지원하지 않음 → **팀이 파일을 만들어 두고, 사장님이 앱에서 직접 올림(반자동).**
- 언제: 틱톡 네이티브 영상을 예약하는 날마다 1개(트렌드 = 매일, 셀럽 = 묶음 날).
- 무엇: 1080x1920 세로 jpg 1장 또는 5~10초 mp4(배경음 없이 무음 — 사장님이 앱에서 음악 고를 수 있게). 오늘 틱톡 영상을 보러 가게 만드는 **예고**: 오늘 그림·장면 중 가장 눈에 띄는 것 꽉 + 큰 후킹 한 줄(틱톡 영상과 다른 문장, 정답은 안 알려주기) + "오늘 영상 프로필에서 ↑" 같은 안내. 새 그림 생성 금지(오늘 재료만).
